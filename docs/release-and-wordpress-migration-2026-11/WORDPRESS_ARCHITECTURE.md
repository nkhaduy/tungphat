# Kiến trúc WordPress headless cho blog

Quyết định: **NOT READY**. Adapter thử nghiệm đứng riêng; frontend hiện vẫn dùng Payload. `cms.mdftungphat.com` đang phục vụ Payload production, không phải hostname trống. WordPress cần hostname mới và hạ tầng riêng do chủ website chọn; không sửa DNS trong Phase 6.

Mục tiêu: Gutenberg → REST API công khai cho bài published → build Next.js static → `/bai-viet/{slug}/`. WordPress sở hữu title, slug, nội dung, excerpt, ảnh, alt/caption, taxonomy, trạng thái, ngày và metadata biên tập; Next.js sở hữu route, canonical, sitemap, JSON-LD, breadcrumb và giao diện. Product/catalogue tiếp tục Payload/hệ hiện tại. [WordPress REST posts](https://developer.wordpress.org/rest-api/reference/posts/) phân biệt `publish`, `draft`, `future`, `private`; phân trang phải được xử lý đầy đủ.

Publish/update/unpublish/schedule sau khi trạng thái thực sự chuyển published → webhook xác thực HMAC timestamp + event ID → service có durable dedup/rate limit/debounce → build deployment mới → chỉ đưa vào phục vụ khi build đạt; log trạng thái, retry có backoff và cảnh báo, phục hồi bằng build lại. `lib/wordpress/webhook.ts` mới kiểm tra chữ ký/timestamp và gọi interface claim nguyên tử; endpoint, storage durable, secret, hàng đợi, build trigger, retry và staging **chưa triển khai**; static export không nhận cập nhật tự động. Không công khai build hook; không dùng webhook WordPress chưa xác thực trực tiếp.

Preview draft cần runtime riêng có xác thực người dùng biên tập, token ngắn hạn, HTTPS, không cache công khai, noindex/no-store, không ghi draft vào static/sitemap; API credentials chỉ server. Nếu static host không chạy runtime cần preview bridge hoặc staging Next riêng. Chưa có bridge, xác thực, hoặc preview thực tế; không nhầm `/cms-preview/` hiện hữu với preview WordPress.

Trước cutover: backup WordPress/database/media đã kiểm tra khôi phục, TLS, least privilege, cập nhật core/plugin, 2FA, giám sát và chống lộ secrets. REST body và nội dung HTML phải qua sanitizer allowlist đã kiểm thử XSS, URL và nguồn ảnh HTTPS được phép; không render HTML thô. Phải xác nhận Gutenberg table/figure/caption, `<img>`, internal links, SEO metadata và các tag/attribute được hỗ trợ. Ảnh, block lạ, script, iframe, URL độc hại, redirection và outage phải fail closed; staging không được phép xuất nhầm draft. Không thêm WPGraphQL hoặc plugin khi chưa có nhu cầu.

Primitive local dùng HMAC-SHA256 trên `timestamp.body`, thời hạn ±5 phút, so sánh constant-time, giới hạn body 256 KiB và ID sự kiện; consumer phải cấu hình WordPress phát đúng giao thức. Interface claim phải atomic và durable, không phải Map trong process. Trước khi nối build phải dùng queue/outbox durable đồng bộ với claim để retry an toàn khi build fail hoặc process dừng; chỉ trả accepted sau khi việc xếp hàng được bảo đảm, không coi duplicate là build đã thành công. Chưa có endpoint hoặc khả năng kích hoạt build.
