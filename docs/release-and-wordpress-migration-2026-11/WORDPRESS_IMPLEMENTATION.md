# WordPress: phần đã triển khai và giới hạn

- `lib/wordpress/posts.ts`: adapter REST độc lập, **chưa được nối** vào `getArticles`, route, sitemap hay renderer; mặc định website vẫn đọc Payload. Chỉ nhận HTTPS không userinfo/query, chặn redirect, duyệt tối đa 50 trang và fail khi pagination thiếu/bất nhất hoặc API lỗi; loại status không publish, nội dung được bảo vệ và bài ngày tương lai; kiểm tra slug duy nhất và tạo canonical domain frontend. Các trường HTML trả về có nhãn không tin cậy, tuyệt đối chưa render. Không có credential hay endpoint production được thêm.
- `lib/wordpress/webhook.ts`: primitive HMAC/timestamp và interface claim; không có endpoint, durable store hay build trigger. Lỗi storage fail closed. Cần durable outbox/queue và retry trước khi tích hợp; claim một mình không bảo đảm build hoàn tất.
- `tests/wordpress-adapter.test.ts`, `tests/wordpress-migration-fixture.test.ts`, `tests/wordpress-webhook.test.ts`: fixture test publish/draft/future/private/protected, phân trang, trùng slug, API lỗi, missing header, update/unpublish/delete, canonical, HTTPS và 3 bài nguồn có figure/bảng. Đây là mock, không chứng minh WordPress thực sự hoặc parity output.
- `fixtures/final-payload-articles.json`: 3 bài đã hợp nhất body và HTML article từ renderer local; không phải migration import, backup media hoặc bản duyệt.
- Đã chạy `vitest run tests/wordpress-adapter.test.ts tests/wordpress-migration-fixture.test.ts tests/wordpress-webhook.test.ts`: 10/10 đạt; eslint các file adapter/webhook và test exit 0. Không thay đổi router, sitemap, material/canonical hay Payload production.

**Chưa triển khai:** WordPress host/admin/editor, xác thực preview, sanitizer/render Gutenberg, ảnh và taxonomy mapping, metadata SEO đăng ký qua REST, converter/import Gutenberg, migration parity, webhook xác thực/dedup/rate limit/build/retry, build/deploy thực, staging và rollback end-to-end. Adapter chỉ nhận output công khai và chưa giữ đủ dữ liệu để phục vụ cắt chuyển; instance/outage 404 và quyền truy cập thực chưa kiểm chứng. Do đó **NOT READY**, không STAGING READY hay CUTOVER READY. API outage phải chặn build mới, giữ deployment cũ; không fallback âm thầm sang Payload sau cutover.
