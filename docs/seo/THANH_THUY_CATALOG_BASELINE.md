## Current architecture

- Framework: Next.js 15 App Router with `output: "export"` and `trailingSlash: true`.
- Content: Markdown + frontmatter in `content/`, parsed by `lib/content.ts` and validated with Zod schemas in `lib/content-schema.ts`.
- CMS: Decap CMS configuration in `cloudflare-cms/public/config.yml`; published product content is stored in the repository and statically exported.
- Existing product routes: root product pages at `/<slug>`, product index at `/san-pham/`, brand pages at `/san-pham/[brand]/`, and catalogue pages at `/catalogue/[brand]/`.
- SEO: metadata helpers in `lib/seo.ts` and `lib/content-metadata.ts`; JSON-LD rendered by `components/JsonLd.tsx`; sitemap and robots are generated by `app/sitemap.ts` and `app/robots.ts`.
- Images: local files under `public/`, Next Image configured as unoptimized for static export; existing image validation runs through `scripts/check-images.mjs`.
- Build/deploy: `npm run build` exports `out/`; Cloudflare Pages is configured through Wrangler. No production deploy is performed by this branch.
- Quality gates: Vitest, ESLint, TypeScript, static-output checks, sitemap-output checks, and Playwright suites are present.

## Duplicate/cannibalization risks

- Existing root product slugs are a separate content system from the new Thanh Thuy taxonomy. Putting imported codes at root would collide with the existing catch-all route and compete with MDF/MFC pages.
- Existing `/san-pham/[brand]` can collide with category slugs such as `melamine` and `laminate`.
- Source URLs use `/product/...`; reusing them would make Tùng Phát appear derivative and would create a second canonical system.
- Filter and search combinations can create crawl traps if emitted as indexable query URLs.
- The source has many image/title-only records. Indexing every code page would create a large thin-content cluster.

## Chosen integration

- Store normalized records in `data/catalogs/thanh-thuy/catalog.json`; keep raw crawl cache outside Git under `.cache/thanh-thuy/`.
- Add a rerunnable pipeline under `scripts/thanh-thuy/` with discovery, crawl, normalization, import, validation, retry/backoff, checksum dedupe, dry-run, resume, and rollback support.
- Use stable Tùng Phát URLs: `/thuong-hieu/thanh-thuy/`, `/san-pham/<category>/`, `/san-pham/<category>/<product-slug>/`. Product slugs include `thanh-thuy`, a code when available, and a normalized name.
- Keep `/san-pham/[brand]` for existing non-Thai brands and categories through a controlled dispatcher; Thanh Thuy gets the dedicated brand route.
- Generate local responsive WebP media with content hashes; no source-domain hotlinks are emitted.
- Index the brand page, unique category/series pages, and only product records meeting the quality gate. Other imported code pages are useful `noindex` detail pages and remain searchable.
- Build search/filter as client interaction on the brand/category pages without creating indexable query-parameter routes.
- Add `Product`, `ProductGroup` where applicable, `BreadcrumbList`, `ItemList`, `WebPage`, and existing site organization schemas. No `Offer` is emitted without real price/currency/availability.

## Risks

- Catalogue ownership and image usage should remain covered by Tùng Phát's supplier/distribution relationship; attribution is kept in data and a restrained source note, not copied marketing text.
- Source content may change or temporarily disappear. The importer never deletes published records merely because a crawl fails.
- Product titles can contain ambiguous codes. Records without reliable codes are marked `NEEDS_ENRICHMENT` and are not indexable until reviewed.
- The base checkout is four commits behind `origin/main`; this branch intentionally starts from the requested current HEAD and does not merge or deploy production.
